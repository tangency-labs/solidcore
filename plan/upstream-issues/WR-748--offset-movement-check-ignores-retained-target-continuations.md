#### WR-748. Offset movement detection excludes the target continuations used by construction

- **Severity:** Wrong result
- **Area:** Offset faces and local operations
- **Location:** `offset::offset_faces::on_target`, `move_faces`; local-operation target-support observation.
- **What happens:** the movement check drops nine result-face points onto the original replacement surface, bounded by its original natural parameter domain. Local operation can legitimately extend that support to intersect stationary neighboring faces. Points on that retained continuation then fail the membership test, and an actually moved body is refused as `NoEffect`. This is independent of full-body validation. Conversely, searching the whole extended support can select a remote turn or negative-radius continuation instead of the zero-distance point in the retained face. The membership query must preserve the constructed support and identify the valid inverse branch.
- **Trigger:** positive .1 flank-only offsets of native segmented and continuous external M20 threads and continuous internal M20 threads. The continuous external result has radial ranges `[-.03379999,.88163007]` and `[.11836993,1.03379991]`, beyond the target inputs' `[0,1]`. Moving all lateral faces together does not produce the same refusal.
- **How found:** source tracing and native operation-result inspection after refusal. The operation leaves its constructed body available; it is manifold and has moved offset supports. Separate small corner errors were not bypassed by this investigation.
- **Confirmed:** Rust only; no C++ reference execution claimed. The fork used surface provenance marks, whereas this port implements membership geometrically because its surfaces do not have independent attribute identities.
- **Correction:** the movement check obtains the actual constructed supports of selected local-operation faces, using the existing faceuse-to-offset-face correspondence before that correspondence is cleared. Supports are captured after the existing pre-merge geometry shrink, and before boolean merging can combine face attributes. Each observation carries an exact geometry snapshot with its face's UV domain; the geometric membership test is bounded by that stored domain, independent of later lazy-support growth. Pre-merge domains may still include unused continuations. The face sample's UV is supplied to the existing inverse solver only when exact target evaluation at that UV has already verified the same point within the unchanged body tolerance. An unrelated or differently parameterized support receives no unverified hint. Actual returned 3D gap still decides membership. No new retry or inverse algorithm is introduced. The snapshot has no topology owner. No extension algorithm is duplicated, no tolerance changes, and face marks alone do not establish membership. Existing public local-operation entry points keep their behavior; an internal variant requests the observations.
- **Regression:** the existing offset-faces unit-test module verifies actual local-operation support observation on a bilinear sheet and rejection of the unchanged support. A second native fixture constructs an eight-turn rational ruled surface with a .1 offset, extends it by 40, and retains `[1,31] x [.2,.8]`. An unseeded query over its full extension returns a wrong-branch gap of .1366255 at a retained corner. A geometrically verified hint recognizes the point even over that broad domain. Shifted and reversed parameterizations also pass with their corresponding retained domains, and a different offset support is rejected. The trimmed sheet uses explicit UV rectangle lines and exact curve-on-surface boundaries, and passes strict validation. No thread API or imported fixture is required. The previously refused continuous external +.1 flank-only operation completes with a manifold body passing strict Level2 validation after the verified-hint correction. Native signed external/internal thread checks remain integration evidence.
